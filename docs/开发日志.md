# 启航导航 · 开发日志

按时间顺序记录这个项目怎么一步步变成现在这样：做了什么、为什么这么做、踩过什么坑。
设计规范正文在 `启航导航-开发规范.html`，逐个决策的完整理由在 `docs/adr/`。

---

## 2026-10-01 · 立项

**起点**：想要一个个人自用的网址导航起始页，"最精简"。

**第一轮需求澄清**（问了很多轮才问清）确认下来的是：个人起始页、分类分组 + emoji 图标、
搜索过滤、页面内增删改、多设备可见、单用户认证。当时选的技术形态是
**纯本地 `file://` 打开 + OneDrive 同步**，四个文件、零依赖。

**随后需求一路升级**，每一轮都推翻了一部分前面的结论：

| 轮次 | 新要求 | 后果 |
|---|---|---|
| 1 | 要在页面上增删改 | 浏览器无法从 `file://` 写盘 —— 引出了"必须有个能写盘的通道" |
| 2 | 所有浏览器都要能改 | Safari / Firefox 永远不会有写盘 API → 只能靠服务端 |
| 3 | 要登录认证、要离线 | 认证必须服务端校验；离线要 PWA |
| 4 | **上云，不再自己开发** | 转向找现成开源项目 |
| 5 | 现成项目都不合适 | **回到自建**，但这次是"静态 + 边缘函数"的云端形态 |

## 2026-10-01 · 选型调研（结论都被推翻了，过程仍有价值）

- **开源项目方案**：`eallion/favorite`（CloudNav，基于 EdgeOne Pages，但许可证是 GLWT 玩笑许可、
  作者声明"代码我一无所知"）、`xiejiahe/nav`（发现导航，GPL-3.0 且维护至今，但要求"免费使用必须公开可见"）。
  两者都带一大堆用不到的功能。→ 放弃。
- **免费托管平台**：实测大陆可达性，`vercel.app`、`workers.dev`、`huggingface.co` 被 DNS 投毒；
  Oracle 强制信用卡、Render 免费层无持久磁盘。能同时满足"免费 + 不绑卡 + 真持久化 + 大陆可达"的只有
  **Cloudflare Pages/Workers** 和 **腾讯 EdgeOne Pages**。

## 2026-10-01 · 第一版：`file://` 静态页

四个文件（`index.html` / `style.css` / `app.js` / `data.js`），零依赖、零构建。

- **ADR-0001**：数据写成随页面加载的 JS 数组，**禁用 `fetch` 和 ES modules**——
  两者在 `file://` 下都会被 CORS 拦。这条约束后来随着上云作废了，但"经典脚本"的写法留了下来。
- 用无头浏览器实测出来的两个 bug：
  1. `.gate { display:flex }` 覆盖了 `[hidden]` 的默认样式 → 登录门和主页面同时显示
  2. 网址输入框用了 `type="url"`，浏览器原生校验会拒绝 `example.com` 这类裸域名，
     而我们代码本来就会自动补协议 → 表单根本提交不出去

## 2026-10-01 · 第二版：腾讯 EdgeOne Pages

按 EdgeOne 约定部署，**构建与部署本身完全成功**（日志 `Found Functions directory at /functions`，
控制台缩略图正确渲染出页面）。但——

**撞上决定性限制**：控制台分配的默认域名 `*.edgeone.cool` 对所有路径返回
`401 / X-EOP-MSG: eo_time missing`，要求带签名的访问链接（有效期 3 小时）。
即 **EdgeOne Pages 免费版实际上要求使用者拥有自己的域名，含中国大陆加速还必须 ICP 备案**。
文档没明写，是部署之后才撞上的。

期间修正了一个会让线上静默失效的问题：EdgeOne 把 KV 注入成**以绑定名为名字的全局变量**，
不是 `env.NAV_KV`。改成 `kvOf(context)` 优先取全局、回退取 `env`，
**这个兼容后来正好让代码零改动迁到了 Cloudflare**。

## 2026-10-01 · 迁移到 Cloudflare Pages（ADR-0004）

代码**一行未改**：两边都是标准 Web API + `functions/` 目录约定，而 `kvOf()` 恰好兼容两种注入方式。

- 构建配置：框架预设「无」、构建命令 `exit 0`、输出目录 `/`
- **ADR-0002** 的架构落地：KV 单键整份文档读写、口令在边缘函数里服务端校验
- 上线后实测：`git push` 自动部署正常

> 排障教训：我一度误判"push 不触发部署"，依据是没刷新的部署页截图 + "已删除的文件仍返回 200"。
> **验证部署版本要看新提交里"新增"的文件，不要看"删除"的文件**——删除会受边缘缓存影响。

## 2026-10-01 · 功能迭代

### 分类改为一页一分类
原先所有分类平铺在页面上，改为头部**分类导航**、内容区只渲染当前分类，
URL 带 hash（`#/c/<id>`）以便刷新保持位置。搜索则跨全部分类、按分类分组展示。

### 站点图标（ADR-0003，后经修订）
- 实测：Google / DuckDuckGo / favicon.im 的图标服务**在大陆全部不通**，只能服务端自己抓
- 抓取策略：**先解析首页 HTML 找 `<link rel="icon">`，失败再退 `/favicon.ico`**，
  且**必须校验 `content-type` 是图片**——`cloud.tencent.com/favicon.ico` 返回的是 `200 + text/html`
- 抓到的缓存进 KV，从自己域名发出；也支持**手动上传覆盖**
- **后续修订**：图标接口原先为了 `<img>` 能取图而对所有人开放，理由是"图标本身是公开的"。
  这个推理有漏洞——**图标公开不代表"你收藏了哪些站点"公开**。
  改为登录后种下 HttpOnly Cookie（存口令的 SHA-256，不存明文），图标接口一并要求认证。

### 内网地址不再尝试抓图标
CCJ 分组 33 条里 **21 条是内网地址**（`192.168.x.x` / `10.x.x.x`），边缘节点永远抓不到，
原逻辑会为每条挂 1.5 秒、浏览器同域名并发只有 6 个 → **首屏多等约 5 秒**。
现在识别私有网段后立即放弃（实测 **2 毫秒** vs 1.5 秒）。

### 导入 CCJ 分组
从 `浏览器书签_MIS.html` 导入 37 条，去重和清理后 **33 条**入库。
注意这个文件的 `<a>` 标签**没有闭合**，按正则匹配会把多条粘成一条，必须按 `<a` 边界切分。

### 样式改为紧凑行式
卡片每张 125px 高、带边框和描述行，33 条要 1297px 才装得下。改为参照 `浏览器书签_MIS.html`
的行式文字链接（6 列、6px 间距、蓝色文字、悬停高亮）：同样 33 条约 500px，**密度提升约 2.5 倍**。
小图标保留但缩到 16px。

## 踩过的坑（改代码前先看这里）

1. **KV 的取法**：EdgeOne 用全局变量、Cloudflare 用 `env`。`kvOf(context)` 两者都兼容，别改成单一写法。
2. **函数目录必须是 `functions/`**，不是 `edge-functions/` 或 `node-functions/`。
3. **Cloudflare 新版控制台默认走 Workers 流程**，那条路不认 `functions/`；
   创建项目要走「需要使用旧版 Pages 工作流？继续前往 Pages」。
4. **构建输出目录填 `/`**（站点在仓库根）。填错会部署出一个白页——比构建失败更难排查。
5. **`[hidden]` 会被类选择器上的 `display` 覆盖**，需要显式 `[hidden]{display:none!important}`。
6. **网址输入框别用 `type="url"`**，会拒绝裸域名，和自动补协议的代码打架。
7. **渲染顺序不能改**：必须先 `GET /api/data`（种下 Cookie）再渲染图标，否则图标请求没有凭据。
8. **验证部署版本看"新增"的文件，不看"删除"的**。
