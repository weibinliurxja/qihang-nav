# 自建精简版 + EdgeOne Pages + KV 单文档整份读写

## 背景与决策

试过采用现成开源项目两条路后放弃：CloudNav（`eallion/favorite`）许可证是 GLWT 玩笑许可、作者声明「代码我一无所知、Bug 自己 fork 处理」；发现导航（`xiejiahe/nav`）虽然 GPL-3.0 且维护至今，但它要求「未授权免费使用必须公开可见」，而我们的书签需要私密。两者还都带来大量用不到的功能（AI、天气、小组件、导入导出、多用户）。

因此改为自建：纯静态三文件 + 一个 EdgeOne Pages 边缘函数，样式严格依据 `docs/启航导航-开发规范.html`。

三个关键取舍：

1. **存储用 KV 单键整份文档，而不是按条目的增删改接口。** 每次保存 POST 整份 JSON，覆盖写入。代价是最后写入者获胜、没有并发保护；对单用户这是可接受的，换来的是不需要设计条目级 API、不需要处理删分类时链接的迁移、保存即原子。
2. **口令在边缘函数里校验，而不是依赖平台功能。** EdgeOne 有托管层一键密码保护，但那条对「Git 部署 + 带函数的项目」是否生效未见明确文档；写在函数里则确定可用，且数据从不离开服务端。代价是页面外壳本身是公开的（里面没有数据）。
3. **不做离线/PWA、不做深色模式、不做拖拽排序。** 规范是纯浅色磨砂玻璃；一个人用，静默降级比功能齐全重要。

## 后果

- 数据量上限受 KV 单值 25 MB 与账户 1 GB 限制，对个人导航页远远够用。
- 多人同时编辑会互相覆盖。出现第二条编辑通道时，必须改成条目级接口或加版本号乐观锁。
- `dev-server.mjs` 直接 import 生产用的 `functions/api/data.js`，只替换 KV 绑定，所以本地验证过的就是上线代码；改动函数签名时要同步改这个开发服务器。
